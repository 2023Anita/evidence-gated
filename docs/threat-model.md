# 信任边界

## 保护目标

减少跳步、越界修改、失效报告复用、未签署规格、漏跑检查和自报完成。
每个任务只支持指定低风险纯函数 profile，不能扩展成任意 Shell 调度。

## 受信任与不受信任

| 对象 | 信任条件 |
|---|---|
| 插件治理代码、Schema、策略、公钥 | 由维护者保护并固定版本 |
| 任务合同、计划、基线 | 只有匹配受信任签名后才作为批准内容 |
| 业务源代码与项目测试 | 不可信执行输入 |
| 本地状态、日志和报告 | 可修改缓存，不是授权 |
| CI JSON | 需要与实际平台运行和受保护工作流绑定 |
| GitHub 就绪状态 | 实际平台查询，仍需平台规则正确配置 |

## 实际实现

- 固定验收器 ID，合同不能传入 Shell 或降低最低必需检查。
- 不执行候选仓库的安装脚本、pytest 配置或任意命令。
- 只将两个批准的源/测试文件复制到临时执行树，不挂载整个项目或 `.git`。
- Docker 后端固定镜像摘要、无网络、只读挂载、非 root、无 capabilities、有资源限制。
- stdout 有界，超时终止进程组；容器运行结束或超时后清理此次创建的容器。
- 本地 `--local` 只隔离 Python 进程和环境变量，**不是 OS 安全沙箱**，仍有当前用户文件权限。
- 业务代码在测试前后重新计算摘要；发生变化则拒绝。
- `.gitignore` 不决定检查范围；符号链接、子模块、大文件或超出文件数量上限会拒绝。
- 固定跳过 `.git`、`.egw`、`.venv`、`__pycache__`，这些目录不会复制进候选执行树。

## 无法保证

Agent 拥有治理写权限、审批私钥、管理员 bypass 或宿主全部权限时，插件不能限制其所有动作。
任意恶意程序可能针对已知测试投机、修改同进程测试行为或伪造自身输出；隔离主要保护执行边界，不构成程序正确性的数学证明。
签名能证明所配密钥签署了内容，不能证明批准者认真阅读。当前 profile 的测试也不能泛化证明所有软件功能正确。

本地原子写入与文件锁用于恢复和并发冲突检测，不宣称完全抵抗同账号恶意竞争写入。文件系统快照前后检查不能覆盖每一种 TOCTOU 攻击。

## 平台规则

只把 YAML 写入仓库不会启用 Required Check。同名 check 也不能单独证明来自指定验证器。
必须保护真实工作流来源、治理引用与批准者公钥，并配置分支规则。`workflow/policies/github.json` 默认 `unconfigured`，不能返回就绪。

`protected-workflow` 是维护者完成平台引导后的配置断言；当前代码不会自动配置或完整审计所有套餐的保护规则。平台 API 验证当前 head、目标分支、人工审查、合并状态、指定工作流与 job，并再次读取 head 防止普通状态竞态。
实际合并仍由 GitHub 当时的规则判断；CLI 不执行合并。
